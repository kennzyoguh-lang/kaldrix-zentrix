AI agent payment authorization, explained

Authentication says who is asking. Authorization says what they may do. For an agent that can move money, authorization has to be exact, narrow, expiring and checkable by someone other than the agent.

Authentication is not authorization

A login, a password, a multi-factor code or an API key proves who is asking. After that, the account usually allows whatever the account is allowed to do, for as long as the session lasts. That is fine for a person who can be trusted to use judgement. It is a poor fit for an agent that follows instructions found in text. The question that matters for an agent is not "who are you?" but "what exactly may you do right now, and who said so?"

What a signed capability is

A capability is a signed statement that says: this agent may pay these suppliers, up to this much, for this purpose, until this time. It is signed by the person or system that has the authority, so it cannot be forged or edited. Two properties make it strong for money:

  • Narrowing only. If an agent hands work to another agent, it can pass on a slice of the permission, never a bigger one.
  • Proof of possession. Holding the permission is not enough. On each request the agent signs the exact payment (amount, recipient, currency) with its own key. A proof made for 200 cannot be stretched to 450, and a copied permission is useless without the agent's private key.

What to check on every request

  1. The signature on the permission is valid and it has not expired or been cancelled.
  2. The agent's proof matches this exact payment.
  3. The payment is inside the per-payment limit, the running total and the speed limit.
  4. If the amount is above the approval threshold, a named human has approved this exact payment.
  5. The result is written to a record that cannot be changed quietly, and if the record cannot be written, nothing happens.

A second check before the money moves

One system saying yes is a single point of failure. In Kaldrix and Zentrix, Kaldrix decides, and Zentrix, the payment side, checks the signature again, applies its own limits and only then sends the payment. Either one can say no. Every successful payment returns a signed proof envelope showing who held the permission and exactly what was authorised.

Standards you will see around this

x402 describes how an agent pays for something over the web. AP2 describes signed mandates that capture what a person allowed. MCP describes how an agent gets tools. They are complementary: the protocols say how an agent asks and pays, and an authorization layer says whether it should. See spending limits for x402 and checking AP2 mandates.

Questions people ask

What is the difference between authentication and authorization for AI agents?

Authentication proves who is asking. Authorization decides what they may do. An agent that is logged in can still be tricked, so the limit has to be on the action, not the login.

What is proof of possession?

The agent signs each request with its own private key, so a stolen or copied permission does not work without that key.

Why bind a proof to one exact payment?

So a proof for one amount and one recipient cannot be stretched to pay a different amount or a different recipient.

Do I still need multi-factor authentication?

Yes, for the people who sign and approve. It protects the door. Signed limits protect the money behind it.
