Temporary permissions for AI agents

An agent that runs for a minute should not hold a credential that lasts a year. A permission should exist for the task, be as narrow as the task, and be gone when the task is.

The problem with long-lived keys

A key that lasts for months and can do anything the account can do is a standing invitation. If an agent is tricked, or its key is copied, the damage runs for as long as the key lives and as wide as the key reaches.

What a good temporary permission looks like

PropertyWhy it matters
Short life, from seconds to hoursAccess ends by itself. A task that takes sixty seconds gets sixty seconds.
A start time as well as an endA permission can be issued ahead of a scheduled job and only work in its window.
Signed, so it cannot be editedThe agent cannot extend its own time or widen its own reach.
Only narrower when handed onIf an agent gives work to a sub-agent, the sub-agent gets a slice. Never more, never longer.
A stated purposeEvery request must say what it is for, and must match.
Bound to the agent's own keyA copy of the permission is useless without the key; each request carries a proof for that exact request.
Cancellable at onceOne call and the next request is refused, including for everything handed on from it.
Self-freezing when probedAn agent that keeps asking for things it was never given is stopped automatically.

Using it for payments and for data

The same permission shape works for spending (which supplier, how much per payment and in all, how fast, when a person must approve) and for data (which tables, operations, columns and rows). In Kaldrix a data permission can be five seconds long, a payment permission as short as a minute, and either can be delegated to another agent only in a narrower form. See limiting database access and stopping overspending.

What to be careful about

  • Clock skew. Use the server's clock for checks, not the agent's.
  • Revocation freshness. A verifier that keeps its own copy of the cancellation list may accept a cancelled permission until it refreshes. Keep that window short.
  • A thief inside the window. A short life bounds the loss, it does not prevent it. Pair it with limits on amount and speed, and a person for the large ones.

Questions people ask

What is a short-lived credential for an AI agent?

A permission that exists for one task and ends on a clock, rather than a key that lasts months.

Can an agent extend its own permission?

Not if the time is written into a signed permission. Changing it breaks the signature.

What happens to permissions an agent hands to another agent?

They can only be narrower, shorter and no more able to pass on. Cancelling the parent cancels the child.

Is a short life enough?

No. It bounds the loss. Combine it with limits on amount and speed, a stated purpose, and a person for the large ones.
