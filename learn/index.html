Plain-language guides to AI agent payments.

How to stop an agent overspending, how payment authorization works, and how x402, AP2 and MCP fit together. Written by the people building Kaldrix and Zentrix, with the limits of what we have built stated plainly.

GUIDE

How to stop an AI agent from overspending

A rule written in an agent's prompt is a suggestion. One clever message can argue the agent out of it. A real spending limit lives outside the agent and is checked at the moment of paying.

GUIDE

AI agent payment authorization, explained

Authentication says who is asking. Authorization says what they may do. For an agent that can move money, authorization has to be exact, narrow, expiring and checkable by someone other than the agent.

GUIDE

x402 spending limits for AI agents

x402 lets a web server ask for payment and an agent pay it. The protocol does not say how much an agent may spend in total, whom it may pay, or when a person must approve. That has to be added.

GUIDE

AP2 mandate verification for developers

AP2, Google's Agent Payments Protocol, records what a person allowed an agent to pay as signed mandates. Two jobs follow: verify the signatures, then check the actual payment against the constraints inside them.

GUIDE

Human approval for AI agent payments

Letting an agent pay is useful only if a person does not have to approve everything. The skill is choosing the few payments that need a human and making that approval mean something.

GUIDE

MCP payment tools: how to keep them safe

The Model Context Protocol (MCP) lets an AI assistant call tools. A payment tool is the highest-stakes tool you can add. These are the questions to ask before you do.

GUIDE

AI agent payments in Nigeria and across Africa

Most tools for agent payments talk about cards, dollars and stablecoins. Many businesses in Nigeria and across Africa pay suppliers by bank transfer through local payment providers. That changes what an agent needs.

GUIDE

How to limit what an AI agent can do in your database

Give an AI agent a database login and you have given it everything that login can do, to anyone who can get words in front of it. The limit has to be on each statement, outside the agent, for a stated purpose and a stated time.

GUIDE

Escrow for AI agents: pay only when the task is proven

A payment trigger is fine for a fraction of a cent. A multi-step task needs the money set aside and released only when the work is proven, and the proof has to be something an agent cannot fake by saying so.

GUIDE

Temporary permissions for AI agents

An agent that runs for a minute should not hold a credential that lasts a year. A permission should exist for the task, be as narrow as the task, and be gone when the task is.
