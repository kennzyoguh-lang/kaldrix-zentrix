Escrow for AI agents: pay only when the task is proven

A payment trigger is fine for a fraction of a cent. A multi-step task needs the money set aside and released only when the work is proven, and the proof has to be something an agent cannot fake by saying so.

Why an agent needs escrow

If an agent pays first and the supplier does nothing, the money is gone. If the agent pays after the supplier says "done", a hijacked agent or a lying supplier can still trigger payment. Escrow separates the two: the money is set aside up front, and released only when a condition that can be checked is met.

What a proof has to be

  1. Tied to one exact task. The instructions are hashed when the escrow is made. A proof for a different task does not fit.
  2. Tied to the actual outputs. The escrow lists the outputs the task must produce and the SHA-256 of each. A different or missing file fails.
  3. Signed by a key named in advance. The agent signs a statement over the escrow, the task hash, the time and the output hashes with its own key. A signature from any other key, or for any other escrow, fails.
  4. Fresh. A proof with the wrong time fails, and too many refused proofs close the escrow to proofs.

What else should hold

  • A person, when you want one. Some escrows should also wait for a named person to approve.
  • Authorization again at release. The agent should have to present its permission with a fresh proof for the payment at release, so a permission cancelled in the meantime stops the money.
  • One release only. Two callers racing to release the same escrow must not both succeed. Use a state change only one caller can win.
  • A deadline and a refund. An escrow nobody completes should end by itself and go back, and the owner should be able to refund it while it is locked.

What Zentrix does

Zentrix, the payment side of Kaldrix and Zentrix, implements this as a conditional escrow. The agent's permission is checked when the escrow is made (asked and given back), the proof of completion is checked as above, an optional person approves, and the release goes through Kaldrix a second time before the payment is made once. The test service has ten end-to-end tests for it, including a wrong output, a stranger's signature, a permission cancelled after the task was done, a timeout, and an agent key trying to approve its own escrow.

What "locked" means today. In the test service the money is pretend: locking is a hold recorded in a pretend bank. A real escrow means a licensed provider holding the funds in a segregated account. That is not built, and no provider has agreed to it.

Questions people ask

What is conditional escrow for AI agents?

Funds are set aside for a task and released only when a checkable condition is met, such as a signed proof from the agent that it produced exactly the outputs the task required.

How can an agent prove it finished a task?

By signing, with its own key, a statement over the escrow, the task hash, the time and the hashes of what it produced. The service checks the key, the task and the outputs.

What if the agent's permission is cancelled before release?

The release goes through Kaldrix again, so a cancelled permission stops it. The funds stay locked until a refund or the end time.

Is this real escrow?

Not yet. In the test service the vault is a hold in a pretend bank. A real vault needs a licensed provider.
